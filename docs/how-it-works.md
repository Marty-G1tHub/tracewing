# 工作原理与边界

## 为什么回程必须在 VPS 侧测
Internet 路由是**非对称**的：本机 traceroute 只显示“本机 → 服务器”的路径。要看“服务器 → 国内”，只能从服务器那一侧发起探测，所以有 agent。没有服务器登录权限时，只能测去程，界面会明确写出，不会用去程冒充回程。

## 数据流
```
客户端 ──GET /v1/challenge──▶ agent         （取无状态 nonce，自带签名与时间戳；无需令牌）
客户端 ──GET /v1/route/targets  Authorization: TW <nonce> <proof> ──▶ 固定目标表 + 能力
客户端 ──GET /v1/route/trace?target=ct-bj|…|client ──▶ agent 逐跳 ICMP ──▶ 原始跳数据
客户端：用内置前缀表把每一跳 IP 映射到 AS，按顺序判定线路，给出证据 + 置信度
```
agent 只回传 `{ttl, ip, rtt, 发/收}`；判定规则升级只需更新客户端。

## 判定规则（`internal/route/classify.go`）
先把每一跳映射到骨干 ASN（目标本身所在的 AS 不算证据），再按有序序列判定：

| 条件（按顺序匹配） | 结论 | 置信度 |
|---|---|---|
| 出现 AS4809（含 59.43.0.0/16），同时有联通/移动骨干（4837/9929/58807/58453） | 混合 | 混合 |
| AS4809 之前先出现 AS4134 | 电信 CN2 GT | 确定 |
| AS4809 之后才出现 AS4134（接入段） | 电信 CN2 GIA（末段混有 163 地址） | 混合 |
| 只有 AS4809 | 电信 CN2 GIA | 确定 |
| AS9929（可与 AS4837 同时出现 → 混合） | 联通 9929 / 9929+4837 混合 | 确定 / 混合 |
| AS58807 / AS58453 / 仅 AS9808 | 移动 CMIN2 / CMI / CMNET | 确定 |
| 仅 AS4837 / 仅 AS4134 / 两者都有 | 联通 4837 / 电信 163 / 混合 | 确定 / 确定 / 混合 |
| 只识别到零散地址，或没有可识别地址，或探测不完整 | 无法确定（写明原因） | 无法确定 |

目标自身的地址不计入证据。

`59.43.0.0/16` 不在 BGP 里公告（RIPEstat 查不到），所以前缀表里手工补充；其余来自 RIPEstat 公开数据，同一 ASN 的子前缀已合并以缩小体积。**这些规则是行业经验，不是运营商官方标注**，结论只是“证据支持”，不是保证。

## 探测实现
- Windows：`IcmpSendEcho` + TTL，无需管理员。
- Linux：原始套接字（`CAP_NET_RAW`）发 ICMP Echo，收 Echo Reply / TTL 超时 / 不可达，用内嵌原包的 (id, seq) 匹配；无权限时降级为 dgram ICMP（只有 echo，没有逐跳）或 TCP 握手延迟。
- 每跳默认探测 2 次（单次超时 1.2 s），最多 30 跳，8 路并行，到达目标后截断。路由器对 ICMP 超时报文常常限速，所以个别跳 / 个别目标可能“无回应”，这会让结论降为“无法确定”而不是出错——多测几次即可。

- 单元测试：前缀匹配、多种判定场景、假探测器的并发与截断、原始回包解析、agent 接口（拒绝任意目标 / 额外参数 / 未认证 / 无权限 501 / 限速）、客户端到 agent 的端到端。
- `tests/netns_route.sh`：用 Linux 网络命名空间搭 `agent → r1(59.43.0.1) → r2(202.97.0.2) → r3(12 个目标)` 的假骨干网，让真正的原始套接字 ICMP 走一遍，断言 12 条回程的逐跳地址与判定。
- 没有覆盖：真实公网的路由行为、真实 systemd 下的服务启动（安装脚本在“测试前缀”模式下验证了下载 / 校验 / 令牌 / 单元文件生成，单元文件通过了 `systemd-analyze verify`）。
